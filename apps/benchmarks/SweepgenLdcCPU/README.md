# SweepgenLdcCPU

The benchmark measures the throughput (MLUP/s) of the `SweepgenLbmCPU` LBM sweeps (D3Q19, SRT,
compressible, generated by sweepgen) in a lid-driven cavity instead of a fully periodic box. The
timed loop is stream/collide, the halo exchange between blocks, and the wall sweeps.

## Scenario

The walls are those of waLBerla's `UniformGridCPU` LDC scenario
(`UniformGridCPU/simulation_setup/benchmark_configs.py`, `ldc_setup`):

- north face (y max): a lid moving with velocity (u_lid, 0, 0), u_lid = 0.05 (`UBB([0.05, 0, 0])` in
  `UniformGridCPU.py`), as velocity bounce-back (lbmpy `UBB`);
- west, east, south, bottom and top faces: no-slip walls, half-way bounce-back (lbmpy `NoSlip`);
- relaxation rate omega = 1.8 (`Scenario(omega=1.8)`); the fluid starts at rest with density 1.

A lattice link from a fluid cell into a cell outside the domain belongs to the lid if that cell has
y > y max, including the lid's edges and corners, and to the no-slip walls otherwise. This is what
the flag-based `UniformGridCPU` setup does in effect: its border cells get both flags, and the
boundary collection runs UBB after NoSlip (`lbmpy_walberla/templates/BoundaryCollection.tmpl.h`).
The link sets are disjoint, so the order of the two wall sweeps does not matter. The app checks that
the lid has 5 · Nx · Nz links.

One block of `cells`³ per MPI process; the blocks form the grid `math::getFactors3D(processes)`, so
the cavity grows with the number of processes (e.g. 128 × 128 × 64 for 4 processes of 64³).

## Variants

The same 11 variants as `docs/presentation3` builds of SweepgenLbmCPU; the bulk sweeps are generated
with exactly the options of `SweepgenLbmCPU.py`:

| executable | bulk sweeps | compiler flags |
|---|---|---|
| `SweepgenLdcCPU_scalar[_cse][_cse_aa]` | `Target.GenericCPU` | `-march=rv64gc` on RISC-V, `-fno-tree-vectorize` elsewhere |
| `SweepgenLdcCPU_autovec[_cse][_cse_aa]` | `Target.GenericCPU` | waLBerla's flags: the compiler may auto-vectorize |
| `SweepgenLdcCPU_explicit_cse[_pf]`, `..._explicit_cse_aa[_pf]`, `..._explicit_cse_aa_split` | `Target.CurrentCPU`, vectorized: RVV on RISC-V, AVX on x86 | waLBerla's flags |

`_cse`: lbmpy's global CSE. `_pf`: software prefetch 128 bytes ahead (RVV only, so these two cannot
be generated on x86). `_aa`: in-place AA streaming. `_split`: the direction-split AA stream/collide
of `../SweepgenLbmCPU/lbm_split.py` (imported from there). See `../SweepgenLbmCPU/README.md`.

The wall sweeps are sweepgen `SparseBoundary` sweeps (index lists of links, built with
`fromLinks`). They are generated for `Target.GenericCPU` in every variant, so all executables share
the same wall code. sweepgen's `SparseBoundary` only indexes for the pull pattern; for AA,
`ldc_boundaries.py` generates one sweep per time-step parity (`NoSlipEven`, `NoSlipOdd`, `UBBEven`,
`UBBOdd`) with lbmpy's `BetweenTimestepsIndexing(..., "aa")`.

## Time loop

- pull: `StreamCollide`, `streamPullSync`, `NoSlip`, `UBB`
- AA: `StreamCollideEven`, `aaPullSync`, `NoSlipEven`, `UBBEven`, then `StreamCollideOdd`,
  `aaPushSync`, `NoSlipOdd`, `UBBOdd`

The wall sweeps never run before the first step: `InitPdfs` leaves the slots of PDFs that point
into a wall unwritten.

## Run

```
[SWEEPGEN_LDC_OUTPUT=last] [SWEEPGEN_LDC_DUMP=<prefix>] SweepgenLdcCPU_<variant> [cells per block and direction = 64] [timesteps = 200] [warmup = 10]
```

Each run prints one line:

```
SweepgenLdcCPU variant= compiler= real_t= blocks= domain= cells= steps= warmup= output= omega= u_lid= seconds= mlups= energy= mass= fieldhash= links_noslip= links_ubb= t_bulk= t_comm= t_bc=
```

- `seconds`, `mlups`: one timer around the timed steps (as SweepgenLbmCPU).
- `energy` (sum of |u|²) and `mass` (sum of rho): sums in double precision over the last step's
  fields, printed with 17 digits. The sums depend on the summation order, which depends on the block
  decomposition.
- `fieldhash`: XOR over all cells of a hash of the global cell and the bit patterns of rho and u
  (+0 and -0 hash alike). It depends neither on the order nor on the decomposition: equal hashes
  mean bit-identical fields.
- `links_noslip`, `links_ubb`: number of wall links.
- `t_bulk`, `t_comm`, `t_bc`: rank 0's time in the stream/collide sweeps, the halo exchange and the
  wall sweeps during the timed steps.

`SWEEPGEN_LDC_OUTPUT=last`: only the last step writes rho and u (default: every step).
`SWEEPGEN_LDC_DUMP=<prefix>`: each process writes its cells (global coordinates, rho, u in double)
to `<prefix>.rank<r>.bin` after the run, for the verification scripts.

## Verification

The outer repository's `scripts/presentation4/` checks every build: `verify.sh` compares the fields
cell by cell with an independent NumPy implementation of the same algorithm (`ldc_reference.py`),
on several domains and decompositions, and checks that one block and eight blocks give
bit-identical fields; `check_build.py` audits the compile flags and the vector instructions;
`check_walls.py` checks that the wall code is identical in all variants. Results:
`docs/presentation4/presentation4-progress-opus5.5.md` in the outer repository.
